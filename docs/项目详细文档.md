## 1. 项目概述

### 1.1 用途

在工业产线上自动识别罐子/瓶子的正反方向（正罐 vs 倒罐），通过工业相机拍照、深度学习模型推理、PLC 自动剔除不合格品。

### 1.2 技术栈

| 层级 | 技术 |
|------|------|
| 前端框架 | Electron 28 + React 18 + TypeScript |
| 前端构建 | Vite 5 |
| 样式 | Tailwind CSS 3 |
| 状态管理 | Zustand 4 |
| 后端框架 | Flask 3 (Python) |
| 推理引擎 | PyTorch + MobileNetV3-Large |
| 相机 SDK | 海康 MVS (GigE Vision) |
| PLC 协议 | LECPServer HTTP API (Modbus) |
| 打包工具 | PyInstaller (后端) + electron-builder (前端) |
| 目标平台 | Windows 10/11 x64 |

## 3. 后端详解

### 3.1 模块说明

#### `config.py` — 全局配置

```python
class Config:
    CAMERA_COUNT = 4          # 4 路相机
    FLASK_HOST = "127.0.0.1"  # 仅本地监听
    FLASK_PORT = 5000
    DEVICE = "cuda" 或 "cpu"  # 推理设备（自动检测）
    DATA_DIR                # 数据目录: 环境变量 > exe同目录/data > 项目根/data
    INFERENCE_QUEUE_SIZE = 100
    TRAINING_EPOCHS = 100
    MAX_PHOTO_AGE_DAYS = 30
    PHOTO_RETENTION_COUNT = 1000
```

路径优先级:
- `DATA_DIR`: `VISION_DATA_DIR` 环境变量 → `exe同目录/data/` → `项目根/data/`
- `MVS SDK`: 固定路径 `C:\Program Files (x86)\MVS`
- 模型: `data/jar_classifier_<产品名>.pth`

#### `server.py` — Flask API 路由

核心文件 (~2000行)，注册了所有 REST API 端点。

**请求处理流程示意（以启动为例）:**

```
POST /api/start
  → 验证请求参数
  → 读取相机配置
  → 初始化/连接4路相机
  → 设置曝光、增益、触发模式
  → 启动相机工作线程
  → 返回成功
```

**相机工作线程逻辑:**

```
while running:
    1. 等待硬件触发信号 (MV_CC_GetImageBuffer, 阻塞)
    2. 收到帧 → 时间戳记录
    3. 像素格式转换 (Bayer BG8 → RGB8)
    4. PIL Image → 提交到推理队列
    5. 等待推理结果 (poll result queue)
    6. 如果是倒罐 → 写 PLC 剔除信号
    7. 异步保存照片到磁盘
```

#### `mvs_camera.py` — 海康相机驱动

封装海康 MVS SDK 的 C 接口为 Python 类:

- `MVSCamera`: 单台相机操作
  - `connect()` / `disconnect()`
  - `start_grabbing()` / `stop_grabbing()`
  - `grab_frame()` — 阻塞等待硬件触发后的一帧
  - `set_exposure_time(us)` / `set_gain(db)`
  - `set_trigger_mode()` / `set_trigger_source()` / `set_trigger_activation()`
  - `set_line_debouncer_time()` — 去抖
  - `set_strobe_enable()` / `set_strobe_delay()` / `set_strobe_duration()` — 频闪灯
  - `get_optimal_packet_size()` — GigE 性能优化
  - 像素格式转换: 使用 `MV_CC_ConvertPixelType`

- `MVSCameraManager`: 管理所有相机
  - `initialize()` / `finalize()` — SDK 生命周期
  - `enumerate_cameras()` — 枚举 GigE/USB 设备
  - `create_camera()` / `get_camera()` / `remove_camera()`

#### `inference_worker.py` — 推理队列

**设计要点:**

- **单线程**: 避免 PyTorch 多线程竞争问题
- **微批处理**: 5ms 收集窗口，合并同时到达的多帧为 batch，一次 GPU 前向传播
- **多模型缓存**: 不同产品型号使用不同模型，按 `camera_product_map` 路由
- **设备热切换**: `reload_all_models(device)` 支持 CPU/GPU 切换

**推理流程:**

```
推理 worker 主循环:
  while True:
    等第一帧 (blocking get)
    → 5ms 内非阻塞排空队列收集更多帧
    → 按产品模型分组
    → 每组 batch 推理 (classify_frames_batch)
    → 结果分发到各相机 result_queue
```

#### `training.py` — 模型训练

**模型架构:**

```
MobileNetV3-Large (预训练, ImageNet)
  └── features (frozen 前10轮, 然后微调)
  └── classifier 替换为:
      Linear(960 → 128)
      → LayerNorm
      → ReLU
      → Dropout(0.4)
      → Linear(128 → 2)
```

**预处理流程:**

```
PIL Image (任意尺寸)
  → LANCZOS resize 短边=320
  → 裁剪罐身: 左右去 15%, 上下去 8%
  → square pad 到 max(w,h)
  → resize 224×224
  → float32 normalize [-1, 1]
```

**数据增强 (训练时):**

```
RandomHorizontalFlip(0.5)
RandomVerticalFlip(0.1)
RandomRotation(15°)
ColorJitter(brightness=0.3, contrast=0.3, saturation=0.2, hue=0.05)
RandomAffine(translate=0.08, scale=0.9-1.1)
RandomPerspective(distortion=0.1, p=0.3)
```

**训练策略:**

- 损失函数: CrossEntropyLoss + label_smoothing=0.1
- 优化器: AdamW (两阶段 LR: head=0.001, backbone=0.0001)
- 学习率调度: CosineAnnealingWarmRestarts (T_0=20, T_mult=2)
- 混合精度训练: torch.amp (仅 GPU)
- 梯度裁剪: max_norm=1.0
- 早停: patience=15
- 模型检查点: 按验证准确率保存最佳模型

**推理函数:**

- `classify_single(model, pil_image)` → `(label, confidence)`
- `classify_frames_batch(model, frames)` → `[(label, confidence), ...]`

**数据集格式:**

```
标注模式 (推荐):
  folder/正/*.jpg      → label=0 (正罐)
  folder/反/*.jpg      → label=1 (倒罐)

双目录模式:
  upright_dir/         → label=0
  inverted_dir/        → label=1

自动模式 (降级):
  folder/*.jpg         → label=0 (原图)
                       → label=1 (旋转180°)
```

#### `plc_service.py` — PLC 控制

通过 LECPServer 的 HTTP API (`plc_write_node`) 写 Modbus 寄存器:

- **DWord 时序参数** (每个相机):
  - `VW0/VW2/VW4/VW6`: 触发延时 (trigger_delay)
  - `VW8/VW10/VW12/VW14`: 剔除时间/延时

- **Byte 剔除信号** (每个相机):
  - `MB0/MB1/MB2/MB3`: 写非零值 → 触发剔除

每个相机可配置独立的 PLC URL。

#### `camera_config_manager.py` — 相机配置持久化

JSON 文件存储 (`data/camera_config.json`)，每个相机字段:

| 字段 | 类型 | 说明 |
|------|------|------|
| enabled | bool | 是否启用 |
| ip | string | GigE 相机 IP |
| name | string | 显示名称 |
| triggerSource | string | 触发源 (Line0/Line1) |
| triggerActivation | string | 触发沿 (RisingEdge/FallingEdge) |
| triggerTimeout | int | 触发超时 ms |
| triggerDelay | int | 触发延时 μs |
| exposureTime | int | 曝光时间 μs |
| gain | float | 增益 dB |
| lineDebouncerTime | int | 去抖时间 μs |
| strobeEnable | bool | 频闪灯启停 |
| strobeDelay | int | 频闪延时 μs |
| strobeDuration | int | 频闪持续时间 μs |
| rejectTime | int | 剔除信号持续时间 ms |
| rejectDelay | int | 剔除延时 ms |
| plcUrl | string | PLC 服务地址 |

#### `env_check.py` — 环境检测

系统启动时运行，检查项:

1. MVS SDK 安装路径存在
2. Python 位数与 SDK DLL 一致
3. MVS SDK 可导入和初始化
4. GigE 协议栈可用

#### `logger.py` — 日志系统

- 控制台输出: INFO 级别
- 文件输出: DEBUG 级别, `data/vision_system.log`
- 格式: `2024-01-01 12:00:00 [INFO] vision_system: message`

## 5. AI 模型与训练

### 5.1 模型结构

```
JarClassifier (MobileNetV3-Large based)
├── backbone: mobilenet_v3_large (pretrained ImageNet)
│   └── classifier[-1] → Identity (替换掉)
└── head:
    ├── Linear(960, 128)
    ├── LayerNorm(128)
    ├── ReLU
    ├── Dropout(0.4)
    └── Linear(128, 2)
```

### 5.2 训练超参

| 参数 | 默认值 |
|------|--------|
| Epochs | 100 |
| Batch Size | 8 |
| Head LR | 0.001 |
| Backbone LR | 0.0001 |
| Freeze Epochs | 10 (前10轮冻结 backbone) |
| Label Smoothing | 0.1 |
| Weight Decay | 1e-4 (head), 1e-5 (backbone) |
| Early Stop Patience | 15 |
| LR Schedule | CosineAnnealingWarmRestarts (T₀=20) |
| Mixed Precision | 自动 (GPU 时启用 AMP) |

### 5.3 模型存储

- 位置: `data/jar_classifier_<产品名>.pth`
- 训练历史: 同目录 `training_history.json`
- 推理时: 按产品名加载对应模型，未指定则加载第一个已训练模型
- 多产品: 不同产品的模型共存，推理时按相机-产品映射路由

### 5.4 训练流程 (API)

```
POST /api/training/start
{
  "uprightPath": "D:\图片\正",      // 正罐图片目录
  "invertedPath": "D:\图片\反",     // 倒罐图片目录
  "folderPath": "",                  // 或: 包含正/反子目录的父目录
  "modelName": "罐子A"               // 产品型号名
}

→ 后台线程启动训练
→ 每轮回调实时推送进度 (GET /api/training/status):
  { running: bool, epoch, total_epochs, train_loss, val_loss, val_acc, progress, message }
→ 训练完成: 模型保存 + 训练历史保存
```

## 6. 相机与硬件集成

### 6.1 相机型号

海康 GigE 工业相机 (MVS SDK 兼容)

### 6.2 工作模式

**硬件触发模式** (生产环境):

```
传感器(光电开关) ──信号──→ 相机 Line0 输入
                            │
                    相机曝光拍照
                            │
                    图像通过 GigE 传至 PC
                            │
                    后端 grab_frame() 拿到帧
                            │
                    推理 → 正罐放行 / 倒罐剔��
```

**相机参数 (生产推荐):**

- 触发源: Line0
- 触发沿: RisingEdge (上升沿)
- 曝光时间: 根据光照调整 (典型 1000-5000μs)
- 增益: 0-6 dB (根据光照)
- 去抖: 50μs (防误触发)
- GigE 包大小: 自动最优 (通常 9000)

### 6.3 PLC 集成

**协议:** LECPServer HTTP API (`POST http://<plc_ip>/api/plc_write_node`)

**地址映射 (每个相机):**

| 相机 | 触发延时 | 剔除时间 | 剔除信号 |
|------|---------|---------|---------|
| Cam1 | VW0 | VW8 | MB0 |
| Cam2 | VW2 | VW10 | MB1 |
| Cam3 | VW4 | VW12 | MB2 |
| Cam4 | VW6 | VW14 | MB3 |

剔除逻辑: 推理结果为"反"时 → 等待 rejectDelay ms → 写 MBx=1 → 等待 rejectTime ms → 写 MBx=0

### 6.4 相机配置持久化

每个相机的配置保存在 `data/camera_config.json`，通过 API 读写:

```
GET  /api/cameras/config/:id     → 读取单相机配置
POST /api/cameras/config/:id     → 保存单相机配置
GET  /api/cameras/config         → 读取全部相机配置
```

## 7. 数据流

### 7.1 检测流程 (一帧的完整路径)

```
1. 传感器触发 ──电信号──→ 相机 Line0
2. 相机曝光拍照 (exposureTime μs)
3. GigE 传输帧到 PC
4. 相机线程 grab_frame() 收到帧 (Bayer BG8 格式)
5. 像素格式转换 → RGB (MV_CC_ConvertPixelType)
6. ctypes buffer → numpy array → PIL Image
7. inference_queue.put((cam_id, image, timestamp))
8. 推理 worker:
   a. 5ms 窗口内收集同模型帧
   b. batch = torch.stack(tensors).to(device)
   c. model(batch) → logits → softmax → (label, confidence)
   d. result_queues[cam_id].put(result)
9. 相机线程拿到结果:
   a. if label == "反":
        sleep(rejectDelay ms)
        plc_write_node(MBx, 1)
        sleep(rejectTime ms)
        plc_write_node(MBx, 0)
   b. 更新相机统计 (detected++, defective++ if 反)
10. 异步保存照片:
    a. 线程池执行
    b. PIL save → data/captures/cam<N>/正|反/<timestamp>.bmp
11. 前端 GET /api/status → 显示最新结果
12. 前端 GET /api/frame/:id → 显示最新帧
```

### 7.2 照片管理

- 保存路径: `data/captures/cam<N>/<正|反>/YYYYMMDD_HHMMSS_xxx.bmp`
- 自动清理: 每 3600s 检查一次，超过 1000 张或 30 天前的最早照片被删除
- 保存开关: 前端可分别控制正罐/倒罐是否保存

## 9. 构建与部署

### 9.1 一键打包

```powershell
.\build_portable.ps1 [-Proxy http://127.0.0.1:10808]
```

**构建步骤:**

1. 环境检查: Python 3.9+, Node.js 18+, venv 激活
2. 构建前端: `npm install` → `tsc` → `vite build` → `view/dist/`
3. 构建后端: `PyInstaller backend.spec` → `backend.exe` (onedir 模式, ~1-2GB)
4. 组装: 复制 backend 到 `view/resources/backend/` → `electron-builder --win --dir`
5. 输出: `releases/视觉检测系统_免安装版/`

### 9.2 输出目录结构

```
视觉检测系统_免安装版/
├── 视觉检测系统.exe        # Electron 应用
├── 启动系统.bat             # 一键启动脚本
├── resources/
│   └── backend/
│       ├── backend.exe      # Flask 后端
│       └── _internal/       # PyInstaller 依赖
├── chrome_100_percent.pak   # Electron 运行时
├── chrome_200_percent.pak
├── icudtl.dat
├── libEGL.dll
├── libGLESv2.dll
├── LICENSES.chromium.html
├── resources.pak
├── snapshot_blob.bin
├── v8_context_snapshot.bin
├── vk_swiftshader_icd.json
└── locales/                 # 多语言
```

### 9.3 启动脚本逻辑 (启动系统.bat)

```
1. start /B backend.exe → 后台启动后端
2. 轮询 GET /api/health (最多 20s)
3. start 视觉检测系统.exe → 启动前端
4. 前台等待前端关闭 → 自动 kill backend.exe
```

### 9.4 PyInstaller 配置要点

- 入口: `backend/__main__.py`
- 模式: onedir (DLL 独立存放，可选择性精简)
- 关键 hiddenimports: torch, torchvision, flask, PIL, numpy
- 不打包模型文件 (运行时从 data/ 目录加载)
